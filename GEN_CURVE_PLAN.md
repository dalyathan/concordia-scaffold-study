# GEN_CURVE_PLAN.md - learning curve and a fair rules-vs-examples comparison (written before any GPU work; train and tune cells only)

## Question
(1) How many of the 100 LoRA training cells does oracle-equivalent single-label supervision (Claude's frozen labels) need before it matches the 100-cell result on the tune cells? (2) With the same cells, learning rate and training length, does the target (Claude's example labels) beat distilling the rule paragraph, and is it the CONTENT taught (the labels vs the paragraph's behaviour) or the KIND of target (hard vs soft)? A descriptive curve read against PREDICTIONS.md; the pass/fail rules of earlier arms are not reused. test2_same, test2_newkey and every earlier test set are never scored, selected on or used for design here (gen_lora.py refuses any split other than train and tune).

## Training subsets (nested, stratified, fixed seed)
demo/gen_curve.py writes demo/gen/curve_subsets.json (sha256 e5025b2a5e9970a4ae75968fea39f8b97c54a77e8fd65065c51d456588a9a29d): N = 10, 25, 50, 100 cells, each a prefix of a fixed per-type permutation of the 100 LoRA cells (numpy PCG64 seed 20261202), so 10 in 25 in 50 in 100; per-type counts (below / at_or_above / no_cost): 4/3/3, 9/8/8, 17/17/16, 34/33/33. Each cell keeps its fixed name variant and three option orders (demo/gen/lora_train_cells.json); N cells = 3N examples. Same generator, rendering, five cyclic orders, selection set B (42 train cells outside the training cells, loop set A and the packet cells) and tune cells (42) as before. The subsets were drawn once (one draw: N is confounded with which cells were drawn; stated as a limit).

## Arms (all lr 1e-4, rank 4, alpha 8, q/k/v/o, fp32 adapter, AdamW, full-vocabulary letter cross-entropy, gradient checkpointing; no lr grid)
- **examples-N** (N = 10, 25, 50, 100; 3 seeds each): one-hot on the letter showing Claude's frozen label (demo/gen/claude_labels.json, sha256 0b6f0feb...; asserted).
- **rule-soft-N** (N = 25, 100): context distillation as in the earlier teacher-distil: target = Gemma's own first-token letter distribution (over the five letters, per case and order) with the frozen teacher paragraph (demo/gen/teacher_method.txt, sha f41ae9b3...) in the prompt.
- **rule-hard-N** (N = 25, 100): the ARGMAX letter of that same distribution as a one-hot target (ties: lowest letter). Same paragraph, same prompt, same cells as rule-soft: only the kind of target differs.
- **cheapest-label-25**: one-hot on the cheapest listed price for every case (cheap-offer control), N = 25.
Seeds: 3 for examples-N; 1 (seed 0) for the others. Existing runs are reused where the procedure is identical (see the length rule: at N = 100 it equals the earlier one): examples-100 = gen_claude_examples_lr1e-04_s0-2; rule-soft-100 = gen_teacher_lr1e-04_s0-2 (3 seeds exist; seed 0 alone is also shown for equal footing with the single-seed arms). New runs (13): examples-10 s0-2, examples-25 s0-2, examples-50 s0-2, rule-soft-25 s0, rule-hard-25 s0, rule-hard-100 s0, cheapest-label-25 s0.

## Training length (exact rule)
Optimizer steps are held constant: one step per training case per epoch, so epochs = ceil(500 / N): N = 10: 50 epochs, 25: 20, 50: 10, 100: 5 (500 steps at every N; the N = 100 rule is identical to the earlier runs). Selection set B is scored at epoch 0 and then at optimizer steps 20, 50, 100, 200, 300, 400, 500 for N = 10 (epochs 2, 5, 10, 20, 30, 40, 50), 50, 100, 200, 300, 400, 500 for N = 25 (epochs 2, 4, 8, 12, 16, 20) and N = 50 (epochs 1, 2, 4, 6, 8, 10), and 100, 200, ..., 500 for N = 100 (every epoch, as in the earlier runs); the early scorings give small N a chance to be stopped before memorisation; the adapter at the lowest selection-set soft regret is kept (epoch 0 only if nothing improves; flagged); early stopping with patience 2 scorings without improvement. The small-N runs do not monitor a train sample. The tune cells (both name variants, five orders) are scored once per run at the best step, for the report only. Optimizer: constant lr, no schedule, no warm-up, the same as before.

## Cost and budget (8 GPU-hours)
Measured on the 100-cell runs: 296 s per 100 steps (2.96 s per step, 3 forward/backward passes), plus about 62 s per selection scoring, 120 s for the final tune scoring and about 2 minutes of loading and target building: about 2100 s = 0.58 GPU-hours per run at 500 steps (early stopping can shorten it). 13 new runs = about 7.6-8.3 GPU-hours (budget 8). Run order (a cut falls on the last runs first; there are no extra control seeds to cut; N = 50 seeds 1-2 come last as the owner specified, but examples-50 seed 0 runs early because the answer to the curve question depends on it): examples-25 s0, examples-10 s0, examples-50 s0, rule-soft-25, rule-hard-25, rule-hard-100, cheapest-label-25, examples-25 s1-2, examples-10 s1-2, examples-50 s1-2. A partly run N = 50 is scored on the seeds that exist and flagged; its predictions become UNCLEAR if the cut removed it entirely. The per-run estimate is now 2300 s (adds the reload re-scoring of set B, target building and the extra scorings): 13 runs is about 8.3 GPU-hours before early stopping, so a cut of the last runs is likely and is part of the plan. Before each run the chain checks max(sum of finished runs' wall_s, elapsed) + the mean measured run time <= 8 h and otherwise skips it and everything after it, logging which runs were cut. The chain commits and pushes after each run and halts if a run fails.

## Report (tune cells only; demo/gen_curve_report.py; descriptive)
Per run and per arm (seeds averaged): soft regret overall and per type, with a paired cell bootstrap (10,000 resamples, numpy PCG64 seed 0, 95% percentile) clustered by decision problem (V, grid, C or prior; the 42 tune cells pose 38 distinct problems, so cells sharing a problem are resampled together); comparisons examples-N minus rule-soft-N and minus rule-hard-N at N = 25 and 100, the curve against plain (0.657), always-cheapest (0.429) and the stated-cost rule (0.214); the slope of the expected offer on the stated cost over the 14 below cells with a cluster bootstrap interval; letter mass; best step and whether epoch 0 was kept; per-seed values next to every mean; the per-type results. Each prediction in PREDICTIONS.md is scored held / failed / unclear by the criteria written there. G2 (Sonnet + Opus) before any conclusion is written.

## Frozen before the first run, and the no-peeking rule
demo/gen/curve_freeze.json records the sha256 of every input (subsets, LoRA training cells, selection sets, Claude labels, teacher paragraph, cells, cases, plain scores, stored text rows), of the six reused N = 100 run files, of the code (gen_lora.py, gen_curve*.py, gen_cases.py, gen_notes.py, core.py, phase3.py, local_gemma2.py), of this plan and of PREDICTIONS.md, and the torch / transformers / peft versions; the chain and the report assert equality (the chain refuses to start on any difference). Every run stores its code sha256 and git head; the report asserts each loaded run's arm, lr, N, training cells and schedule. No change to code, plan, predictions or thresholds after the first run completes; the chain commits every finished run (including its tune scores), but interim reports are not used to change anything. A failed run halts the chain and stays reported.

## Added after gate G1 (reports in reviews/2026-11-23_G1_curve_{sonnet,opus}.md)
Mechanical scoring rule and split probability statements (PREDICTIONS.md); the (V, grid)-clustered bootstrap is the interval used for every "lower bound > 0" condition (the problem-clustered interval is shown too); argmax (hard) regret of every run; the regret of each training target on the training subset (Claude labels 0; the in-prompt teacher paragraph soft and argmax; always-cheapest), share of cheapest labels per subset; distinct training problems per subset and the tune cells they cover, regret on covered and uncovered tune cells at every N; the order-disagreement share of the rule-hard targets; seed-spread yardsticks; per-seed slopes and per-type values for every run; extra early scorings; the freeze record.

## Declared limits
One subset draw; seeds vary initialisation and order only; the constant-steps rule means small N trains many epochs on few cells (memorisation is possible; the selection set decides the stopping step); rule-hard-N is the argmax of one fixed distribution (order-dependent letters, ties to the lowest letter); labels come from a script-solving teacher and equal the oracle up to a lowest-price tie rule, so "examples" here means oracle-like single labels, not human-like teaching; the 42 tune cells were used for earlier arms and verdicts (no multiplicity correction); single seeds for the controls. The learning rate 1e-4 was chosen earlier at N = 100 (on selection set B among {1e-4, 3e-4} for the examples arm; the teacher arm used 1e-4 from its own grid), and 500 steps / five scorings come from the N = 100 recipe, so small N is read as "at this fixed recipe" (a weak small-N result is partly a recipe effect). The nested subsets are ONE draw and seeds do not redraw them, so the curve's intervals exclude subset variance (the owner asked for a fixed-seed nested draw; a second draw of N = 25 would cost about 0.6 GPU-hours and is not in the budget). rule-hard's per-order argmax can give the same case different target prices under its three orders (the disagreement share is logged). The 2x2 is incomplete: there is no examples-soft arm (Claude labels smoothed to the rule-soft entropy; about 0.6 GPU-hours, not in budget). Positive results are about held-out tune cells of the same generator only. Nothing here touches test_same, test_hard, test2_same, test2_newkey, the original study's cells, old adapters or name variants 1-14.
