# G1 review, Fable: LoRA plan (distillation arms with matched controls; 11 train / 6 held-out tune cells)

**Verdict: go-with-changes.** The training path and target construction look correct, but the pass rule can be satisfied by a content-free "offer low" adapter, and the chain script overruns the budget and drops the wrong control first.

Not verifiable from the packet: everything in `refimpl/`, `text_rows.json`, `ledger.py`, any bootstrap or pass-rule code. Nothing was executed; run counts are hand-derived from `lora_chain.py`.

1. **The pass rule does not exclude "always offer low".** Always-2 scores 0.333 on the tune cells against plain 0.577, neutral text 0.531 and wrong-rule text 0.462, so an adapter that only shifts offers down beats all three comparators. All the signal is in the 3 cost-below-resale cells (plain 1.08 there, about 0 elsewhere). Fix: add const2 and the best shuffled derangement to the pass rule; add a frozen content criterion such as the offer-versus-stated-cost slope on the tune cells (plain 0.12) or regret on cells where 2 is not a best offer.
2. **The reduction rule drops the needed control first and still misses the budget** (33, 29, 26, 23 runs; about 19.7, 17.3, 15.5, 13.7 GPU-hours at 330 s per epoch; the script silently falls back to the last). The estimate omits model loading, teacher passes and the fallback run. Fix: keep const2 and cut shuffled (9 runs) to one learning rate first; abort when no plan fits; measure seconds per epoch from the trainability run before planning.
3. **Early stopping on tune-cell regret can leave the controls untrained.** Every arm starts with epoch 0 (plain) as best; a neutral or wrong_rule adapter that drifts from plain may stop at epoch 0–2, so "beats the matched control" collapses to "beats plain". Fix: stop the distillation arms on held-out teacher cross-entropy (needs teacher targets on the tune cases), or a fixed epoch count; report each arm's fidelity to its own teacher and require the controls to have reached theirs before the comparison counts.
4. **No coherence floor.** Loss and metric are both renormalised over five letters, so letter mass (plain 0.64) can collapse while regret looks excellent. Fix: freeze a mass floor relative to plain inside the pass rule; require free-text hard regret to improve too, or scope the claim to the first-token readout.
5. **The trainability check confounds fitting with generalisation** (`train_best` is train regret at the best tune epoch, with patience 2), and the fallback's result is never read: the chain continues at rank 4 whatever happens, and `lora_status.json` omits it. Fix: run the check without early stopping and use the minimum train regret; decide in advance whether a failed check switches all arms to the fallback or halts.
6. **A null is hard to interpret.** The method teacher is weak on the train cells (0.428; 0.69 on cost-below-resale) against 0.171 on tune; a null could mean "bad teacher". Fix: pre-declare an outcome table (student matches teacher on train or not, crossed with transfers or not); state the ceiling (about 0.17 on tune).
7. **Six cells with a percentile bootstrap is fragile.** With only 3 informative cells a resample contains none of them 1.6% of the time and misses any given one 33% of the time; passing effectively requires gains in all three, and the percentile interval is anticonservative at n = 6. The seed asymmetry under the reduction rule is conservative but should be stated. Fix: per-cell differences and all seeds individually; treat the interval as descriptive.
8. **The pass rule has no code, and the checks are not gated.** `lora_checks.py` implements checks 1–3; check 4 is absent; `lora_chain.py` never reads `lora_checks.json`. Fix: write and commit the pass-rule script before training; make the chain refuse to start unless all checks pass.
9. **wrong_rule is not length-matched** (six tokens). Call it a content control.
10. **The split may have been made with outcome knowledge.** It was hand-picked before training, but plain and text-row results on these cells already existed (method text 0.171 on tune vs 0.428 on train). State whether those numbers were visible when the cells were chosen.

Code errors affecting results: `launch` calls `subprocess.run` without `check=True`, so a crashed grid run is skipped and `chosen_lr` picks from a partial grid, defaulting to 3e-4 if nothing finished; the teacher cache is keyed by case and order only, so an edited method or neutral text reuses stale targets; a possible dtype mismatch (float32 adapter weights on a bf16 base) is unverified until check 1 or a smoke run. Checked and correct: target and letter ordering; soft-cap and renormalisation match the scoring path; teachers computed before PEFT injection; run-id formats agree.

Freeze before the single test look: one adapter per arm (rate, seed, epoch) or an explicit seed-averaging rule, with adapter hashes and the code commit; the primary metric, bootstrap unit (18 cells), interval method, and a pass rule including const2, shuffled, the slope criterion and the mass floor; all comparators recomputed in the same run on the test cells (plain, method, neutral and wrong-rule text, always-1 and always-2); free-text scoring and its parser; the reading of each outcome including a null, and a commitment to report either way; a statement that tune-cell numbers are selected-on so the test run is the only independent evidence.
