# G2 blind review of the refactor: Opus

Verdict: **partly justified.** (a) Plug in any model and task holds for task, solver and config interfaces; the model side is untested (no HF solver run, 4 of 5 configs unchecked, the claims checker would mix models). (b) Wrong numbers get caught holds for edits to stored per-case scores or summaries (recompute.py); not for a fabricated whole record, a subset or rerun selection, unbacked README numbers, or any section other than "Results at a glance". Reviewer had Read and Glob only; could not verify the sha256 values, the byte-identical port, test results, or whether `core.steering_cell_split` puts the planted cells in "test".

1. No fresh locked split; the guard does not enforce "once". test_same and test_hard already show 7 arms in RESULTS_GENERATED.md; test2 not ported. Any `G3-OWNER-GO:` string unlocks; token not stored in the record; no check for an earlier look; `write=False` leaves no record; `task.cases("test_same")` unguarded; import_legacy scores test splits directly. Fix: name the fresh split; for locked splits force write=True, store the token, require an owner-written entry pinning the solver-config hash, refuse if a record already exists for (task, split, model, config); check `case_ids_sha256` against demo/gen/fingerprints.json.
2. Planted cases do not catch the known failure (plain Gemma "offers about 2 regardless"): planted-below has answer 2, planted-atabove accepts 1, 2 or 3; `ConstantSolver(option=1)` passes 2 of 3; a uniform or broken readout ties to index 0 and passes atabove; a letter-to-option mapping bug cannot show for the oracle (same mapping); no reported number has planted cases yet. Fix: plant cases whose answers are 4 or 5 or need the cost; require a probability margin, count ties as failures; assert planted cells are not old-test cells.
3. `check_claims.run_mean` selects by solver and split only: ignores task, model and solver_config, averages every record found (reruns, preflights, deleted bad seeds change the "seed mean" silently; with a second model "plain/tune" mixes models); make_report likewise. Fix: evidence lists exact record paths with sha256; filter by task, model, config hash.
4. The claim checker misses numbers: `kind: none` passes unless `--strict` (test not strict; five unbacked: 0.12, 1, 0.58, 0.17, 0.2); `file_value` evidence not hash-pinned; numbers inside a claim's text but not listed count as covered; `shown in text` is a substring test ("0.1" matches "0.12"); the ignore list ["2","9","1"] hides every bare 2, 9 or 1; numbers written as words not scanned; only one section scanned (problem tree and History not, though CLAUDE.md requires evidence there). Fix: strict in the test, sha256 per evidence file, every number match in a claim's text must be listed, exact-context ignores, scan the tree and History.
5. Recompute is internally consistent only and not enforced on runs/: cannot check option-order handling because records keep option-space per_order_probs, not raw letter probabilities plus the letter-to-option map; does not check probs equal the mean of per_order_probs, hard regret per case, by_type, planted flags, or the case set equal to the canonical split; `zip` truncates on length mismatch; no test runs recompute.py over runs/. Fix: store raw letter probs and the map per order, recompute the averaging, compare case-ID hash to a frozen fingerprint, add a pytest over runs/.
6. The scorer lock catches only accidental edits: the same agent can edit the scorer and paste the new PROTECTED line; a hash anywhere in DECISIONS.md, even an old one, passes; code outside protected/ (letter-to-option mapping and averaging in evaluate.py, payoffs() delegation, case generation) not covered. Fix: review `git log -p harness/protected DECISIONS.md` at each gate; pin hashes in an owner-held file and add evaluate.py to it.
7. A misconfigured model can still get through: Backend checks only non-null ids, does not re-derive them from the tokenizer; no revision pinned; letter mass has no floor so a wrong-token readout is renormalised into plausible numbers; the Llama 3.1 template inserts today's date so prompts change by date; letters fixed to a..e so at most 5 options. Fix: assert ids at load, pin revision per config, flag or refuse below a mass threshold, pass date_string for Llama.
8. Generator overwrite risk: `python -m harness.tasks.haggling` writes to demo/gen/ by default, the reference for the byte-identical test and fingerprinted by test_look_lock; fingerprint comparisons skip when the Concordia clone is missing. Fix: default to a scratch directory, refuse to overwrite.
9. Minor: git dirty ignores untracked files; gpu_seconds excludes model load; make_report header points to the non-existent test_report_fresh.py; `test_haggling_baselines_ordering` asserts `c < u + 1` (nearly vacuous); check_citations checks only the first citing location of each id with loose title match; one Backend shared between the LoRA solver and others would leak the adapter (latent).

Before the single test look, freeze: which split is fresh; GPU readout parity against legacy on tune; model revision, verified letter ids and a mass floor; each arm's exact config with hashes and the seed list; primary metric and aggregation, comparison threshold, CI method (bootstrap clustered by cell, since the n0/n1 variants share a cell); planted policy (does a failure void the run?); protected hashes, clean commit and CLAIMS entries for the expected numbers written in advance.
