# G2 blind review of the refactor: Sonnet

Verdict: **partly justified.**

(a) Plug in any model or task: structurally supported (one YAML per model, a task protocol, a test that shared code names no model) but never shown with a real model. HF solvers unrun; four of five configs NOT CHECKED; gated-model layer counts and hidden sizes typed by hand. Holds for CPU solvers and the toy task only.
(b) Wrong or invented numbers get caught: only for edits made after a record is written; not for a wrong record, a wrong solver or a wrong case set.

Problems, ranked

1. The locked-split guard is not a guard. Any string starting `G3-OWNER-GO:` unlocks a split; the CLI has `--lock-token`; `locked_splits` is a task attribute (a new task can declare none); nothing records or enforces "scored once" (`write=False` leaves no trace; run ids carry timestamps); `task.cases("test_same")` is directly reachable; cases are regenerated at run time and `cases_sha256` is compared with nothing frozen; `fingerprints_v2` (the only labelled fingerprint) is permanently skipped in the port test, and the fingerprint test skips without the Concordia clone. Fix: committed ledger of looks written by the owner; token = hash/HMAC of {task, split, solver, model, case-set hash, date}, single use; evaluate refuses a differing `cases_sha256`; guard in protected code.
2. A changed scorer or payoff can still get through. Authority is DECISIONS.md, unprotected, edited by the same actor, substring match; old hashes stay valid forever (revert passes). Not protected: evaluate.py (averaging, means), task.render, orders, planted_expected, case builders, check_claims. The protected payoff reads case fields from unprotected code. Fix: pin hashes outside the experiment's write access (CI with required reviewer, or a git tag); protect evaluate.py and order/averaging code; accept only the newest, unique hash line.
3. A fabricated or erroneous record is accepted if internally consistent. recompute.py checks payoffs, sum to 1 and regret arithmetic; it does not check `probs` equals the mean of `per_order_probs`, nor case ids/inputs against the frozen set (cherry-picked subset passes; `n_cases` never compared with an expected count). Nothing proves probabilities came from a model; the readout is unrun and has no parity check. Fix: verify order-mean, compare case-id hash and expected count to frozen values, require a GPU parity run with tolerance set beforehand.
4. check_claims is weaker than documented. Docstring says it re-derives from per-case rows, but `run_mean` reads stored `score.soft_regret` (an edited per-case score passes; only recompute.py would catch it and nothing runs it on `runs/`). `run_mean` selects by solver and split only (ignores task, model, preflight/duplicate records). Any number inside a claim span counts as covered even if not listed. `decimals` is author-set, not derived from the shown string. Unbacked numbers fail only under `--strict`, the test runs non-strict; five README numbers are `kind: none`, so "no number differs from evidence" is vacuous for them. Only one README section scanned. Fix: recompute from payoffs and probs or call recompute; key on task, model, solver; derive decimals; require every number in a span listed; run `--strict` in a test.
5. Headline LoRA numbers not tied to any record: locked-test "0.26 / plain 0.53" come from `file_value` on test_look.json, not per-case rows; the imported records give 0.396 (method, test_same), 0.868 (test_hard), plain 0.694 and 1.297, none matching. Probably a different locked set (test2), not imported or ported. Could not read README or test_look.json; unverified. Fix: import test2 per-case results; mark claims backed only by one self-reported file.
6. A wrongly configured model can pass unnoticed. The letter-id check tokenizes the chat-template output plus a letter: the prompt ends `Answer: (<end_of_turn>` + assistant prefix, so the readout measures the first reply token at the start of the assistant turn, not "the token after the prompt's final '('" as DECISIONS.md says. A model starting with "(" or "The" puts little mass on letters; `letter_mass` is recorded, no floor enforced, renormalisation hides it. `Backend` requires non-null ids, not `"tokenizer" in verified`. Revision defaults to None (weights not pinned). `LoRASolver` replaces `backend.model` with a PeftModel, so a later plain/steering solver on that backend runs with the adapter active. No check that a steering vector shape matches `hidden_size`. Fix: mass floor failing the record; require verified; recompute ids at load; pin revision; use `disable_adapter`/context manager; assert vector shape.
7. Planted cases test less than claimed. On a real model `planted_ok` measures model skill as well as pipeline correctness. Only `top_option` is checked; the all-tie `planted-atabove` accepts 3 of 5 options (random passes ~60%). Expected answers in unprotected task file. By hand the three haggling planted cases are correct. Fix: separate pipeline check (oracle through the real render/order path must score 0) from model sanity; move `planted_expected` into protected code.
8. Smaller: regret of the order-averaged distribution is at most the mean per-order regret and hides position bias (report per-order too); float-noise ties in `top_option` broken by index; unknown split name returns an empty record without error; `git.dirty` recorded not enforced; citation check uses lenient substring matching; report text cites a non-existent test file `test_report_fresh.py`.

Before the single test look: haggling test_same and test_hard were already scored by earlier arms (per the records), so a new "single look" there is not clean; any further claim needs a fresh set or an explicit re-look statement. Freeze in a committed file: arms and primary metric with slice/type reporting rules; decision rule with margins and seed count; model revision hash and dtype; lesson, vector and adapter hashes and verified letter ids; harness commit with clean tree; protected-file hashes; case-set hash and labelled fingerprint; letter-mass floor and planted-pass requirement; handling of failed runs; a second look needs a new set.

Could not verify: that any test passes; README and demo_out files; the byte-identical claim; solver.py, `__init__` files and other YAML configs.
