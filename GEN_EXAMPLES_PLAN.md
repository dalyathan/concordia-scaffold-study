# GEN_EXAMPLES_PLAN.md - Claude teaches by worked examples (written before any training; train and tune cells only)

## Question (reworded after G1)
Does fine-tuning (rank-4 LoRA) on single-price labels from a blind Claude teacher for the 100 training cases lower soft regret on unseen tune cells, and is that more than "it learned to offer cheap" (cheapest-label control) or "any labels at these cells" (shuffled-label control, which differs from Claude's labels in 61 of 100 cases: 30 below, 31 no-cost, 0 at-or-above)? **Plainly:** because the labels equal the oracle up to a tie rule, arm (a) is the answer-trained ceiling with a different tie rule; a pass is expected and would show that oracle-like single-label supervision on 100 cells works, not that a teacher 'taught' anything beyond what the script-solving teacher computed. The new quantity is (a) against the ceiling at the same lr (reported, with a non-inferiority margin of 0.05).

## Arms (same gen_lora.py path, 100 training cells, name variant and 3 orders per case, 300 examples, as the answer-trained ceiling; only the target differs)
(a) **claude-examples:** target = all probability on the letter that shows Claude's labelled price (one-hot).
(b) **cheapest-label control:** one-hot on the letter showing the cheapest listed price, for every training case.
(c) **shuffled-Claude-labels control:** Claude's labelled grid position (0-4) permuted within case type (below, at_or_above, no_cost); among 20000 random derangements per type (numpy PCG64 seed 20261127) the one with the fewest cases receiving a label equal to their own is kept. Computed now: agreement with Claude's labels 4 of 34 below, 33 of 33 at-or-above (all labels are position 0, so that type cannot be shuffled), 2 of 33 no-cost; 61 of 100 labels differ; the per-type share of cheapest labels is unchanged by construction (53% / 100% / 42%). The agreement by type, the label-map sha256 and the code sha256 are stored in each run JSON.
Same loss (full-vocabulary letter cross-entropy), rank 4, alpha 8, q/k/v/o, fp32 adapter, AdamW, one step per case, gradient checkpointing, at most 5 epochs, early stopping patience 2 on selection set B (42 train cells outside the training cells, loop set A and the packet cells), all assertions of GEN_PLAN.md (training path = scoring path, epoch 0 = saved plain, best-adapter reload).
Reference rows already on tune (no new runs): plain 0.657, always-cheapest 0.429, stated-cost rule 0.214, teacher-distil 0.376 (3 seeds), our-method-distil 0.373 (3 seeds), wrong-rule-distil 0.589 (1 seed), answer-trained ceiling 0.118 (lr 3e-4) and 0.026 (lr 1e-4).

## Seeds, learning rate, budget (5 GPU-hours, measured)
Order: (a) lr 1e-4 seed 0; (a) lr 3e-4 seed 0; choose (a)'s lr by the lower selection-set soft regret (ties to the lower lr); (b) seed 0 at that lr; (a) seeds 1-2 at that lr; (c) seed 0 at that lr. Estimate = runs x measured seconds per run (mean wall_s of this chain's finished runs; 2400 s assumed before the first finishes; the earlier runs took 1190-2370 s). 6 runs x 2400 s = 4.0 h, which fits. Before each run the chain checks max(sum of finished runs' wall_s, wall-clock elapsed since the chain started) + estimated next run <= 5 h; if not, it skips it and everything after it: (c) is cut first because it runs last, then (a) seed 2, etc. (the lr grid for the controls is already omitted: (b) and (c) run only at (a)'s lr).
Stop rules: halt if both (a) runs keep epoch 0 (nothing was learned); precondition: claude_labels.json sha256 equals the frozen value and covers exactly the 100 training cases.

## Pass rule (on TUNE cells, frozen now; owner's rule, plus the unambiguous handling below)
Per-cell tune soft regret = mean of the two name variants, then mean over an arm's seeds. (a) PASSES only if ALL hold:
1. (a) beats plain: lower 95% bound of the paired cell bootstrap of (plain - a) > 0 (42 cells, 10,000 resamples, numpy PCG64 seed 0, percentile);
2. (a) beats the cheapest-label control (b): lower bound of (b - a) > 0;
3. (a) beats the always-cheapest baseline (computed from the labels): lower bound of (always-cheapest - a) > 0;
4. cost-below cells (14): lower bound of (plain - a) > 0;
5. no case type (below, at_or_above, no_cost) is worse than plain by more than 0.05 (type mean of a minus plain <= 0.05);
6. letter mass >= 0.9 x plain overall (and reported per type).
Definitions fixed now: all intervals are two-sided 95% percentile intervals; "lower bound" = the 2.5th percentile of the paired cell bootstrap. The always-cheapest baseline = per-cell tune soft regret of always offering the cheapest listed price, computed from the labels on the 42 tune cells (0.429); condition 5 is a point-estimate rule; condition 4 has only 14 cells and low power (a failure of condition 4 alone fails the rule and is reported as such). No run is dropped; a run whose best epoch is 0 is scored as epoch 0 (= plain) and flagged, and a control that keeps epoch 0 is then plain, which is reported. The pass is judged on the owner's rule with the mean over completed seeds (labelled); if (b) is missing the verdict is INCOMPLETE, not PASSED. Tags printed with the verdict (not part of the owner's rule, but they decide how it may be worded): T1 conditions 1 and 2 also hold on the 26 non-overlapping tune cells (label key V, grid, C or prior not among the 100 training cells; 16 tune cells overlap: 9 at-or-above, 5 below, 2 no-cost); T2 conditions 1-5 hold on seeds 1-2 only (seed 0 chose the lr); T3 condition 2 holds with (a) seed 0 against (b) seed 0 (equal footing); T4 on below and no-cost cells separately, (b) minus (a) has lower bound > 0, and (c) minus (a) has lower bound > 0 on those cells; T5 non-inferiority to the ceiling at the same lr (mean difference (a) minus ceiling <= 0.05). Because (a) is expected to pass, the wording of a pass must say which tags hold. Per-seed spread of (a) is shown next to every interval (the bootstrap resamples cells only).
Reported alongside, not part of the rule: the slope of the expected offer on the stated cost over below cells with a bootstrap interval; the mass on the cheapest option by type; (a) minus (c) on below and no-cost cells (the 61 differing cases), with a bootstrap interval; comparison with teacher-distil (gain over teacher-distil, bootstrap) and with the answer-trained ceiling at both rates; by-type tables; by overlap of the label key with the 100 training cells; per-seed values; letter mass per type.
If (a) passes: a test plan is written for the owner's approval (no test scoring). If not: the verdict says so, with no mechanism claim.

## Declared limits
Labels come from a script-solving teacher, so (a) tests "supervised oracle-like labels at 100 cells" rather than "a human-like teacher"; the 100 training cells are few (34/33/33) and label keys overlap with some tune cells (reported); the tie rule makes at-or-above labels all cheapest; (b) and (c) have one seed; no lr grid for the controls; tune was used before for other arms (the verdict here is on tune only, selection on set B); nothing in this plan touches test_same, test_hard, the old test cells, old adapters or name variants 1-14.
